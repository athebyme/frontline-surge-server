# Работа над выделенным сервером Frontline Surge

Этот репозиторий собирает один исполняемый файл на Rust — `frontline-server`. Сервер ведёт матч двух команд в современной промышленной долине. В версии 0.5 побеждает сторона с большим числом устранений по истечении времени. Следующая цель разработки — физический командный узел, который можно оборонять и разрушить. [Правила запуска](README.md) · [Архитектура](docs/architecture.md) · [План штурма](docs/ideas/base-assault.md)

## Порядок слияния

Работай в отдельной ветке. Изменения попадают в `main` только через pull request с успешной проверкой `server-test-build`. Прямой push и force-push в `main` запрещены.

## Когда меняешь механику

- Проводи проверку и изменение состояния в серверной симуляции. Для передачи груза это одна операция с обоими остатками, проверкой расстояния, команды и вместимости. Для добычи и производства считай время в симуляции.
- Учитывай уже подключённого игрока, поздний вход и смену раунда. Пролом в стене должен одновременно менять попадания, проходимость и данные, из которых новый игрок восстановит карту.
- Сохраняй границу с отдельным клиентом. При изменении обязательного поля, смысла команды или списка в снимке согласуй формат обоих релизов. Зафиксируй версию протокола и проверь вход несовместимой версии. Для изменений карты передай клиентской стороне ту же геометрию и порядок объектов.
- Игрок управляет своим бойцом. Права на отладочные команды задаёт сервер при подключении. Проверяй отказ для обычного подключения и условия, при которых разрешён локальный оператор.
- Записывай принятое решение и причину в документацию, а предлагаемое правило с критерием проверки — в бэклог. Пример решения плейтеста и текущие задачи собраны отдельно. [Решения 0.5](docs/decisions/playtest-05.md) · [Бэклог](TODO.md)

## Как проверить изменение

Из корня репозитория запусти `cargo test --locked`. Для отдельной проверки сетевого события есть `cargo test --locked --test dedicated`, для проверки через границу двухчасового раунда — `cargo test --release --locked --test long_match`. В последнем тесте ускоряется игровое время.

При правке карты сначала измени генератор или исходную деревню, затем выполни `python3 tools/make_level.py` и `python3 tools/check_level.py`. Сохрани обновлённый `assets/level.json` вместе с исходником изменения. Сервер встраивает уровень при сборке. [Генератор](tools/make_level.py) · [Геометрические проверки](tools/check_level.py)

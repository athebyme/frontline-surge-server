# Штурм базы

**Проект будущего режима.** Две команды добывают ресурсы, организуют подвоз, укрепляют свою базу и побеждают, уничтожив физический командный узел соперника. Это даёт рейсу за металлом понятную цель даже при отставании по устранениям. В сборке 0.5 сервер подводит итог по командному счёту после истечения времени. [Порядок реализации](../../TODO.md)

## Два физических узла

На каждой базе предлагается защищённая подстанция со стойками управления во дворе. У узла есть команда, координаты, постоянный в пределах сессии идентификатор и здоровье. Новые игроки получают всё это при входе. На карте уровень повреждений читается из тех же серверных данных, которые определяют исход матча.

Стартовый двор включает гараж, пехотный выход, прикрытое возрождение и укрепления. Существующая промышленная карта уже даёт обеим сторонам транспорт и развилки. Места для узлов и расположение стартовых секций ещё подлежат проверке. Для каждой базы нужны два подхода и проходимый выезд, остающиеся доступными после разрешённых построек.

## Оборона и разрушение

Защитник везёт материал и тратит его на ремонт или новую секцию. У построенной или восстановленной секции снова появляется серверная коллизия. Повтор команды от того же клиента и одновременная работа двух защитников должны сохранять запас материала. Цену, предел и задержку ремонта предстоит подобрать так, чтобы один полный рюкзак не позволял бесконечно держать узел.

Во время атаки сервер сначала применяет все допустимые изменения одного тика, затем вычисляет результат по состоянию двух узлов. Предлагается засчитывать ничью, если оба разрушены в этот тик. Финальное сообщение содержит победителя, причину и счёт. Изменения после финала больше не влияют на исход. Список игровых источников урона узлу и возможность ремонта его внутренних стоек остаются открытыми.

## Смена сессии

После экрана результата тот же выделенный процесс создаёт следующий матч. В предлагаемом контракте у сессии есть новый идентификатор. Команды старой сессии отбрасываются, а в исходный снимок попадают целые узлы, свежие материалы, автопарк и чистая карта. При обрыве TCP новый вход должен возвращать полное состояние текущей игры. Сохранение позывного, выбор команды при заполненном составе и правила при пустом сервере требуют отдельных решений.

## Как проверить прототип

1. Два игрока разбили одну секцию. Третий вошёл в этот момент и может пройти через тот же проём.
2. Команда, отстающая по устранениям, уничтожила вражеский узел. Все получили один и тот же итог с причиной окончания.
3. Оба узла потеряны в один тик. Перестановка порядка игроков даёт одинаковый исход, процесс начинает следующий матч ровно один раз.
4. Один игрок сохранил соединение, другой подключился после финала. У обоих одинаковый идентификатор новой сессии, начальное состояние карты и запасы. Команда из старого матча не проходит.
5. Две группы поменялись сторонами. По фактическим времени подвоза, расходу ремонта и длительности осады можно сравнить преимущества баз.
